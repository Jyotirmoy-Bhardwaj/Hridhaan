Evaluation

How we know a rule pack is right

Each rule pack is built against an expert-labelled evaluation set drawn from your own historic decisions. No version reaches production until it clears the gate:

  • Agreement with expert consensus, at a threshold agreed in writing before work begins
  • Zero misses on the criteria you designate as critical
  • Determinism verified — same document, same rule version, same findings, months later
  • Fails closed: anything it cannot assess is escalated, never quietly passed
  • Validation documentation generated by the release, not written afterwards by hand
Deployment

Designed to run inside your tenant

Rule packs and logic arrive as signed, versioned bundles over an outbound connection — the same pattern any licensed enterprise software uses.

  • Confidential proposals, patient data and trade secrets stay in your environment
  • A rule pack version changes when you accept it, and every assessment records which one it ran against
  • Signed offline packages where no outbound connection is permitted
  • Delivered behind network isolation and private endpoints, alongside your security architects

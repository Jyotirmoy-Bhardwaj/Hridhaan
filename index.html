Evaluation

The release gate

Every rule pack is scored against an expert-labelled set built from your own past decisions. No version ships until it clears:

  • Agreement with expert consensus, at a threshold agreed in writing
  • Zero misses on your critical criteria
  • Determinism verified across re-runs
  • Fails closed, never open
  • Validation documentation generated by the release
Deployment

Inside your tenant

Rule packs arrive as signed, versioned bundles — the pattern any licensed enterprise software uses.

  • Your documents never leave your environment
  • Versions change when you accept them, and each assessment records which ran
  • Signed offline packages where nothing outbound is permitted
  • Works best where Azure or M365 is already in place

Connector work and validation support are scoped and priced separately, agreed before work begins.

Why this holds

Model releases commoditise intelligence, not evidence.
